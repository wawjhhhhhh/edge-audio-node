# 接口定义

三套接口：**板子 ↔ 电脑（以太网/UDP）**、**电脑 ↔ ESP32（TCP）**、**PS ↔ PL（AXI）**。全部为小端主机字节序，但协议字段（多字节长度/序号）一律 **大端**。

## 1. 网络层常量

| 项 | 值 |
|---|---|
| 板子 MAC | `02:00:00:00:00:01`（`app_ea_main.c:60-61`） |
| 板子 IP | `169.254.191.50`（静态，`BOARD_IP0..3`） |
| 电脑 IP | `169.254.191.246`（静态，同网段，直连） |
| 板子发出的目的地址 | `255.255.255.255`（全网广播，电脑侧不需要知道板子 IP 也能收） |
| 电脑发给板子的地址 | 必须广播到 `169.254.255.255`（板子不做 ARP 应答，单播会丢） |
| 链路 | 100 Mbps 全双工，自协商 |

端口：

| 端口 | 方向 | 用途 |
|---|---|---|
| 50505 | 板 → PC | 麦克风音频上行（`AU` 帧） |
| 50506 | PC → 板 | 播放 PCM 下行 |
| 50507 | PC → 板 | 控制（1 字节 ASCII） |
| 50508 | 板 → PC | 状态广播（`AS` 帧，4 Hz） |

## 2. 音频上行帧（`AU`，端口 50505）

一帧音频 = 480 word = **1920 B**（10 ms @ 48 kHz 立体声，word = `{L16,R16}`），拆成 **2 个 UDP 包**，每包 968 B。帧率 100 fps → **200 包/秒 → 193.6 kB/s → 1.549 Mbit/s**。

UDP 载荷：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `tag0` = `'A'` | |
| 1 | 1 | `tag1` = `'U'` | |
| 2 | 2 | `seq` | BE16，每包 +1，回绕 |
| 4 | 2 | `chunk` | BE16，帧内块号 0/1 |
| 6 | 2 | `lenfield` | BE16，**整帧字节数 1920**（不是本包长度） |
| 8 | 960 | `data` | 240 word = 半帧 PCM |

接收端判据：`tag` 正确、`lenfield == 1920`、`chunk ∈ {0,1}`；连续两块的 `seq` 必须相邻，否则记一次丢包（控制台 `lost` 计数）。

## 3. 状态帧（`AS`，端口 50508）

每 **250 ms** 一包，UDP 载荷 15 B，全部字段是**板子自己的实测状态**：

| 偏移 | 长度 | 字段 | 取值 |
|---|---|---|---|
| 0 | 1 | `tag` = `'S'` | |
| 1 | 1 | `version` = 2 | v1 解析器会因校验范围不同而整包丢弃（设计如此） |
| 2 | 1 | `dsp_mode` | 0 旁路 / 1 RNNoise / 2 门限 / 3 PL 谱减 |
| 3 | 1 | `ts_rate` | 时长比例 50–100（%） |
| 4 | 1 | `ts_apply` | 1 = 拉伸请求挂起 |
| 5 | 1 | `dly_frames` | 附加延迟帧数（×10 ms） |
| 6 | 1 | `lat_off` | 延迟补偿偏移 |
| 7 | 2 | `gain` | BE16，0–32768 |
| 9 | 1 | `rn_target` | RNNoise 目标延迟（帧） |
| 10 | 1 | `tone_en` | 1 = 测试音开 |
| 11 | 2 | `noise` | BE16，底噪注入 0/300/800/1500 |
| 13 | 1 | `dac_mode` | 双 DAC 模式；**GPIO 读不回来时强制写 3**，表示"这块 bit 里没这个功能" |
| 14 | 1 | `xor` | p[0..13] 异或校验 |

`dac_mode = 3` 是刻意保留的"诚实值"：宁可显示"未生效"，也不显示一个看起来成功、实际没接通的档位。

## 4. 控制面（端口 50507）

单字节 ASCII，无应答（状态由 50508 回读确认）：

| 字节 | 动作 |
|---|---|
| `'0'` | 旁路 |
| `'1'` | RNNoise（PS 侧批量处理） |
| `'2'` | 轻量噪声门 |
| `'3'` | PL 谱减（当前 PL 未接入，等同直通） |
| `'a'..'d'` | 底噪注入 0 / 300 / 800 / 1500 |
| `'t'` | 440 Hz 测试音开/关 |

串口（115200，PL 侧 UART）接受同样的 `'0'..'3'`，用于脱离网络调机。

## 5. PS ↔ PL：AXI GPIO

| 地址 | 通道 | 位定义 |
|---|---|---|
| `0x41200000` | ch1（输出） | bit0 = PL 谱减旁路（BD 里接 `axis_dn/bypass`） |
| `0x41200008` | ch2（输入） | RTL 里是 `{cnt_rx_ovf[7:0], cnt_tx_unf[6:0], key_state, 16'h1022}` |

> ⚠️ 实测教训：在归档的 2026-10-29 bit 上，`0x41200008` 读回 `0xA5B16D1E`——低 16 位不是 `0x1022`，说明**那块 bit 不是由当前仓库 RTL 综合出来的**。因此这个寄存器只能用于"确认 bit 版本"，不能当采集计数用。完整的证据与推论见 `docs/known_issues.md`。

## 6. PS ↔ PL：DMA / AXIS

| 通路 | 方向 | 位宽 | 帧长 | 说明 |
|---|---|---|---|---|
| `axi_dma_a` S2MM | PL → DDR | 32 bit | 480 beat（1920 B） | 每 10 ms 一次，`tlast` 在第 480 拍 |
| `axi_dma_mm2s` | DDR → PL | 32 bit | 4800 word（100 ms ×4 缓冲） | 播放侧，乒乓 4 块 |

两侧均为 `FCLK0 = 100 MHz`；`acc_rx` / `acc_tx` 负责把 50 MHz 的 audio_axis_core 接过来。

## 7. I2S 时序约定

| 信号 | 频率/极性 |
|---|---|
| `aud_mclk` | 12.288 MHz（= 256 × 48 kHz） |
| `aud_bclk` | 1.536 MHz（= 32 × 48 kHz；`aud_mclk/8`） |
| `aud_lrc` | 48 kHz，50 % 占空比，低 = 左声道 |
| 数据 | MSB first，每声道 16 bit，BCLK 上升沿采样，下降沿更新 |

> 注意：`eth_audio_top.v` 的端口注释写着 "aud_bclk 3.072 MHz"，那是早期笔误。以 `slave_signal_gen.v` 的 `bclk_div_cnt == 8'd3` 为准：4 个 MCLK 翻转一次 → 周期 8 × 81.35 ns = 650.8 ns → **1.536 MHz**。写约束时必须用这个值。

## 8. 电脑 ↔ ESP32（TCP 9200）

| 项 | 值 |
|---|---|
| 传输 | 裸 TCP，无应用层包头 |
| 格式 | 16 kHz / 16 bit / 单声道，小端（s16le） |
| 码率 | 32 kB/s |
| 预缓冲 | 32000 B（1 s），写满才开始播 |
| 空闲退出 | 连续 3 次读超时 → 播放线程退出，服务继续监听 |
| 板端 | `host/app/xiaozhi/board/{boot.py,main.py}`（MicroPython v1.29.0） |
| 功放 | MAX98357A：BCLK=GPIO4、WS=GPIO5、DIN=GPIO6 |

## 9. 控制台 HTTP 接口（本机 8770）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 单页控制台 |
| GET | `/api/state` | 全量状态 JSON（`fps/packets/lost/under/dbfs/board{...}/chat{...}`） |
| POST | `/api/cmd` | `{"op": "...", ...}`，见下 |

常用 `op`：`listen`（`{"v":true}` 开始接收）、`mode`、`ts`、`gain`、`dly`、`noise`、`tone`、`chat`（`{"text": "..."}`）、`chat_voice`（`{"v": true}`）、`chat_voice_test`、`chat_clear`。

`/api/state` 里凡是"板子能自己报的"字段，都来自 50508 的 `AS` 帧，不是控制台的本地意图——这是判读"点了有没有生效"的唯一依据。
