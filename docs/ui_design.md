# 端侧音频控制台 · 界面设计规划（v3）

> 状态：设计提案，等拍板后实施。
> 现有实现：`web/`（Web 版，已跑通数据链路）+ `app.py`（tkinter 版，可作备份）。
> 本文只谈「长什么样、为什么这样」；接了哪些线、跑什么数在代码里。

---

## 0. 先诊断：为什么现在这版"能用但不像成品"

三条，都很具体：

| 症状 | 证据 | 后果 |
|---|---|---|
| **一屏塞满** | 观察/推送/控制/日志/预算条 5 块平铺 | 眼睛没有落点，第一秒不知道该看哪 |
| **信息同级** | 帧率、丢帧、目标抖动、隐藏帧、非法包…全是 11px 小字 | 重要和不重要长得一样，等于没有重点 |
| **没有产品意象** | 我们是"实时音频仪器"，但界面上没有一件东西'像仪器' | 评委记不住任何画面 |

ATK 那个界面之所以好看，**不是因为配色，是因为它一屏只放一个鼠标**——信息密度极低，所以每一像素都有分量。

我们的问题不是"不够花"，是**没有取舍**。

---

## 1. 设计目标（只留三条，其余都是手段）

1. **一屏一件事**：每页只有一个主角，其余退成注释级。
2. **有仪器感**：波形、频谱、预算条是我们的"表盘"。它们该占最大的面积，而不是挤在中间一行。
3. **动效必须编码信息**：不做装饰性动画。每一个动效都要回答"刚才发生了什么"。

---

## 2. 信息架构：分 5 页，不要一页

左侧 rail 常驻，主区一次只显示一页。

```
┌──────────┬───────────────────────────────────────────────┐
│ ● 端侧音频 │  顶栏：连接状态 · 当前档位 · 主题             │
│          ├───────────────────────────────────────────────┤
│ 概览      │                                               │
│ 监听      │            主区（一次只放一件事）              │
│ 音源      │                                               │
│ 降噪      │                                               │
│ 关于      │                                               │
│          │                                               │
│ ─────    │                                               │
│ PCB 地址  │                                               │
│ 帧率 100  │                                               │
└──────────┴───────────────────────────────────────────────┘
```

| 页面 | 一句话目标 | 主视觉 | 英雄数字 | 主要操作 |
|---|---|---|---|---|
| **概览** | 30 秒看懂这套系统在干什么 | 链路图（PC→以太网→FPGA→I2S→双DAC）+ 三项体检 | 100 fps / 23.7 dB / 0.127 ms | 一键 A/B、自检音 |
| **监听** | 听清"降噪前 vs 后" | **全宽波形 + 频谱**（占 60% 高度） | 当前 dBFS | 三档切换、录音、增益 |
| **音源** | 把声音送进板子 | 文件/测试音卡片 + 传输进度 | 已发帧/丢帧 | 选 WAV、发送、停止 |
| **降噪** | 讲清"为什么用 0.127 ms 的门" | **10 ms 预算条**（横向可拉伸对比）+ 三档对比 | 预算占比 % | 切档、底噪注入 |
| **关于** | 一页讲完硬件与诚实边界 | 板卡照片 + 参数表 | — | — |

**为什么要分页**：概览页是给评委的 30 秒，监听页是给耳朵的，降噪页是给"为什么要做端侧"这个必问题的。
三件事塞在同一屏，等于三件都没说清。

## 3. 视觉系统

### 3.1 色彩（一套，深色为默认）

| 角色 | 深色 | 说明 |
|---|---|---|
| 背景 L0 | `#0F1216` | 近黑中性，不带蓝调（避免"科技蓝"俗气） |
| 面板 L1 | `#161A1F` | 只比背景亮一档 |
| 卡内块 L2 | `#1D2329` | 指标卡/输入框 |
| 描边 | `#2A3138` | **1px**，不用阴影堆层次 |
| 主文字 | `#E9ECEF` | |
| 次文字 | `#8C949E` | 标签 |
| 弱文字 | `#5A636D` | 注释、单位 |
| **信号色** | `#4C9AFF` | 唯一强调色：选中、主操作、波形 |
| 正常 | `#3FBF7F` | 预算内、在线 |
| 警示 | `#E8A33D` | 峰值保持、超预算提示 |
| 危险 | `#E0574B` | 超预算、丢帧 |

**规则：一屏最多出现 2 个彩色元素**（一个信号色 + 一个语义色）。其余全是灰阶。
现在这版彩色太多（绿条/红条/蓝按钮/橙标签同时出现），这是"廉价感"的主要来源。

### 3.2 字体与数字

- 正文：`system-ui` / 微软雅黑，12–13px
- **所有数字：等宽**（`ui-monospace` / Consolas），用 `font-variant-numeric: tabular-nums`
- 数字层级只有三档：**英雄数字 28–36px**、卡片数字 16–19px、表格数字 12px
- 单位永远比数字小 2 档、且用弱文字色

### 3.3 间距与形状

- 4px 网格；卡内 12/16，卡间 12，区块间 20
- 圆角：卡 14、控件 9、胶囊 20
- 描边 1px；**不用投影**（投影一多就是"模板风"）
- 留白比例目标：主区至少 30% 是空的

## 4. 动效规范

原则：**动效 = 状态变化的可用性提示**，不是装饰。

| # | 动效 | 触发 | 时长/缓动 | 编码的信息 |
|---|---|---|---|---|
| 1 | 在线点呼吸 | 常驻 | 2.4s 无限 | 「还活着」（离线时静止变灰） |
| 2 | 波形左移 | 收到音频 | 逐帧 | 时间在流动 |
| 3 | 频谱衰减 | 每次 FFT | 6 dB/s | 峰值保持，能看出能量落点 |
| 4 | 预算条增长 | 进入降噪页 | 600ms `cubic-bezier(.2,.8,.2,1)` | 「这么小一条 vs 溢出」的对比 |
| 5 | 档位切换 | 点击 | 180ms | 选中态迁移（不是闪烁） |
| 6 | 按钮悬停/按下 | 指针 | 150ms / `scale(.98)` | 可点、已点 |
| 7 | A/B 测量进度 | 跑 A/B | 线性 30s + 分段标记 | 现在测到第几档 |

**禁止**：旋转 loading、粒子、光晕、渐变流动。这类"装饰性动效"在答辩现场只会显得吵。

## 5. 表现力策略：让评委记住三个画面

界面的任务不是"信息齐全"，是**制造三张能被记住的图**。

### 画面一：10 ms 预算条（最强）

一条横轴代表 10 ms。上面画两个块：

- 轻量门：**0.127 ms → 1.3%**，一条几乎看不见的绿线
- RNNoise：**20.07 ms → 201%**，红色块**直接冲出右边界**

旁边一行小字：「硬实时窗口装不下通用模型 → 所以必须自己写」。

**这一张图顶十页 PPT**。它把"为什么用 FPGA"、"我们的取舍"、"技术含量"一次讲完。

### 画面二：同一条数字流，两个 DAC

示意：一条线分叉进两个芯片盒，两个耳机图标同时亮。
配一行：「同一条 48 kHz I2S，板载 CODEC 与独立 SABRE32 DAC 同时解码」。

### 画面三：诚实边界

一个小卡片，三行：

- `旁路` 原始参考
- `轻量门` **主打**：0.127 ms · 100 fps · −23.7 dB
- `RNNoise` **反面教材**：20.07 ms · 49 fps · 听感劣化

**主动展示失败案例**，比宣称"什么都能跑"可信得多。

## 6. 逐页线框

### 6.1 概览

```
┌ 系统状态 ────────────────────────────────┐
│  ● 在线   板子 169.254.191.50            │
│  上行 100 fps · 丢帧 0 · 缓冲 100 ms      │
└──────────────────────────────────────────┘
┌ 链路 ────────────────────────────────────┐
│  PC ──网线──► FPGA(PL I2S 主) ──┬─► ES8388   │
│                                  └─► ES9038Q2M│
└──────────────────────────────────────────┘
┌ 三项体检 ────────────────────────────────┐
│  [100 fps]   [−23.7 dB]   [0.127 ms]     │
└──────────────────────────────────────────┘
      （底部：一键 A/B —— 唯一的主按钮）
```

### 6.2 监听

波形占 60% 高度，频谱 25%，下方一行：三档切换 + 录音 + 增益。
**其余统计全部收进右上角一个「详情」把手**（点开才显示——需求密度高的用户自己去开）。

### 6.3 音源

一张卡片一件事：选文件 → 进度条 → 完成。目标地址/端口收进「高级」折叠。

### 6.4 降噪

预算条占主位，三档对比表次之，底噪注入放底部。

## 7. 一个关键的取舍：两种模式

工程调试需要"一屏全看见"，答辩需要"一屏一件事"。**这是矛盾的**，别硬融。

建议：顶栏放一个开关 **`调试 / 演示`**

- **调试模式**：就是现在这版单页密集布局（保留，别删）
- **演示模式**：分页、大字、大留白、动效全开

答辩时用演示模式；你自己调 bug 用调试模式。同一套数据，两套壳。

## 9. 验收清单（做完自查）

- [ ] 每一页第一秒有明确落点（最大面积 = 最重要的东西）
- [ ] 一屏彩色元素 ≤ 2 处
- [ ] 所有数字等宽对齐，单位弱化
- [ ] 主区留白 ≥ 30%
- [ ] 三个"记忆画面"各能单独截一张图放进 PPT
- [ ] 手机竖屏打开，主要页面可用（不用重做，同一套 HTML）
- [ ] 断网/板子离线时，界面明确说"离线"，不留空白
