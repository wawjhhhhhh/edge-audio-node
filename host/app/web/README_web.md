# PC 端 v3.0：Web 界面与打包

## 为什么换成网页

成熟的控制面板都不是原生工具包画的：

| 软件 | 技术栈 |
|---|---|
| ATK V HUB | Electron（目录里有 `LICENSE.electron.txt`、`v8_context_snapshot.bin`） |
| Realtek Audio Console | WinUI |

圆角、半透明、过渡动画这些能力来自浏览器/现代合成引擎——tkinter 的天花板就在那儿，不是不够努力。

**但不用 Electron**：那要打一整个 Chromium（100 MB+），而我们已经有一个 Python 后端。
这里用标准库起 HTTP 服务，再用 Edge/Chrome 的 `--app=URL` 打开，得到**没有地址栏的独立窗口**。
零额外运行时，而且**手机浏览器打开同一个地址就能用**（同一套页面，自动切成单列）。

```
web/index.html   单文件前端（无外链、离线可用、深/浅主题、5 页）
web_server.py    标准库 ThreadingHTTPServer：/api/state /api/cmd /api/devices
app_entry.py     统一启动器：起服务 + 开窗口（同时是 EXE 的入口）
run_console.cmd  双击启动（走 pythonw，不弹黑框）
```

## 打包成单文件 EXE

```bat
python -m PyInstaller --noconfirm --clean --onefile --windowed ^
  --name ZYNQ-AudioConsole ^
  --add-data "D:\deepseek herness\work\pc_app\web;web" ^
  --collect-data sounddevice --collect-binaries sounddevice ^
  "D:\deepseek herness\work\pc_app\app_entry.py"
```

产物 `dist\ZYNQ-AudioConsole.exe`，约 22 MB，**目标机器不需要装 Python**。

### 三个打包坑（都踩过，别再踩）

1. **不要用 `--exclude-module` 去瘦身。**
   试过排除 `tkinter / matplotlib / scipy`，结果窗口版一启动就**静默退出**（exit 1，无任何输出）。
   原因：`udp_audio` 的依赖链里有东西被连带排掉了，而 `--windowed` 把异常对话框也吞了。
2. **改了参数一定要 `--clean`（或删 `build/`）。**
   `build/` 里缓存的 TOC 会带着上一次的排除项，即使这一次命令行里没写排除，重新分析也不生效——
   这就是"明明改对了还是跑不起来"的原因。
3. **`--windowed` 没有 stdout。** `print()` 在窗口模式下可能直接抛异常，
   所以关键步骤必须落盘：本项目写到 EXE 同目录的 `console-run.log`。

### 生命周期（避免僵尸进程占端口）

| 情形 | 行为 |
|---|---|
| 正常关窗口 | 浏览器进程结束 → 程序退出（存活 >5 s 视为正常） |
| 独立窗口没开出来 | 自动退回默认浏览器，服务**不**退出 |
| 页面关掉但进程还在 | **心跳看门狗**：页面 45 s 不再上报 `/api/state` 就自杀 |
| 端口已被本程序占用 | 识别 `/api/state` 特征后直接开窗口，不重复启动 |

## 声码器（2026-10-31 新增，PC 端试听）

调试模式 → 面板 **05 控制** → 最后一行「声码器」：

| 控件 | 行为 |
| --- | --- |
| 关闭 / 已开启 | 显式下发 `{"op":"voc","v":true/false}`（不做翻转：控制面是 UDP，重复投递是常态） |
| 试听 8 s | `{"op":"voc","v":true,"secs":8}`，后端定时器到点自动关，事件列写「试听结束」 |
| 右侧小字 | 开着时显示 `7.2 kbps · X.XX ms/帧 · 浊音 NN%`，数据来自 `/api/state` 的 `voc` 字段 |

它接在 `jb.pull() → enh.process()` 之后、浏览器播放之前：每 20 ms 只保留 16 个反射
系数 + 基频 + 增益（144 bit = 7.2 kbps），用声道模型把声音重新造出来。噪声没有稳定的
基频/共振峰，进不了这几十个参数，所以原理上被丢掉；代价是「机器人腔」和 20 ms 延迟。
算法与固件侧 `work/eth_audio/sw/vocoder.h` 是同一套（板级接入待做）。

验证：

```powershell
cd work\pc_app
& $py -X utf8 vocoder.py --selftest    # 离线 8 项
& $py -X utf8 test_voc_api.py          # 端到端 19 项（50597/8782，不碰 50505/8770）
```

## 响度与一键 A/B 录音（2026-11-02 新增，包1 证明包）

「听着更响"和"真的更响"经常不是一回事**：人耳对 2–5 kHz 敏感、对低频不敏感。压掉 20 dB
低频噪声和抬 3 dB 中频，在总 RMS 上可能一模一样，只看电平会得出相反结论。所以指标卡上多了
两个 BS.1770-4 的亮度数字，并且提供了一个能把结论"录下来放给评审听"的工具。

| 指标 | 含义 |
| --- | --- |
| 响度（瞬时） | 最近 400 ms 的块响度，LUFS；动作响应快，适合看"我这一下改了什么" |
| 响度（整体） | 会话累计，带 -70 LUFS 绝对门限 + 相对 -10 LU 门限；适合对比 A/B 两档 |

实现在 `work/pc_app/loudness.py`（纯 numpy，K 加权两级 biquad + 400 ms/75 % 重叠 + 双门限），
`python loudness.py` 有 6 项自检。

一键 A/B：

```powershell
# 板子在线、控制台已"开始收听"
python work\pc_app\ab_record.py --modes bypass pl --secs 6 --out 材料库\04-实测记录\AB

# 没板子也能跑（控制台用模拟信号）
python work\pc_app\ab_record.py --sim --modes bypass pl --secs 3
```

它切档 → 等 1.2 s 稳 → 抓 N 秒 `GET /api/pcm`（用户耳朵听到的那一路）→ 存 WAV →
打印「响度 / 噪声底 / RMS / 峰值 / SNR」对照表与相对第一档的差值。判据：pl 相对 bypass
**噪声底降 ≥10 dB、响度差 <1.5 LU**；若几乎不变，先看串口状态行 `dsp=3` 时 `bp=` 是不是 0
（`bp=1` 表示 PL 还在直通，等于没降噪 —— 这个坑 2026-11-02 踩过一次）。

## PC 端增强（2026-11-02 重写：说话时不再把噪声放回来）

「PC 增强」开关用的是 `work/pc_app/pc_enhance_v2.py`（旧版 `pc_enhance.py` 保留对照，不再接线）。

旧版有一行 `psd_eff = noise * (1 - vad)`：VAD 一判"有语音"就把噪声底乘成 0，增益回到 1，
于是**说话时噪声和语音一起出来**、不说话时反而干净——这就是「几乎跟没降噪一样」的来源。
新版把那一行删掉，噪声估计改成**最小统计**（只认最近 1.2 s 最安静的那一帧），说话时它一动不动。

| 环节 | 做法 |
| --- | --- |
| 噪声估计 | 子窗 12 帧取最小 → 8 个子窗再取最小 → ×1.5 补偿 → 0.65/0.35 平滑 |
| 增益 | `g = sqrt(max(0, 1 − α·N/P))`，α=1.6+1.4·s01，下限 −(18+12·s01) dB |
| 平滑 | 频点 3 点（0.15/0.70/0.15）+ 时间一阶（0.55+0.15·p01） |
| 启动 | 前 40 跳（0.4 s）直通，避免开播先掉半秒音量 |

量化判据：`python bench_denoise.py --both`（clean/noise 已知分解，用引擎内部增益 G 算衰减）。

| SNR | 语音段噪声（新 / 旧） | 静音段噪声（新 / 旧） | 语音保留（新 / 旧） |
| --- | --- | --- | --- |
| 5 dB | **6.1 / −6.6 dB** | 21.5 / 7.6 dB | −0.5 / +5.3 dB |
| 10 dB | **7.7 / −6.6 dB** | 21.5 / 8.2 dB | −0.4 / +5.4 dB |
| 15 dB | **8.7 / −6.6 dB** | 21.5 / 7.8 dB | −0.4 / +5.5 dB |

> 旧版"语音段 −6.6 dB"是负的：噪声被放大得比语音还响 —— 与用户听感完全一致。
> 语音段做不到 15 dB 的原因（谐波两侧频点被语音抬高）写在 `pc_enhance_v2.py` 的注释里。

## 播放音效 + 双 DAC 模式（2026-11-02 新增，包2 + 包6）

两件事都作用在**推给板子**的那一路（UDP 50506），与上面的收听链（PC 增强 / 声码器）无关。

### 播放音效（`work/pc_app/playfx.py`）

| 级 | 做法 | 关键参数 |
| --- | --- | --- |
| 均衡 | 10 段 RBJ 峰值串联 | 31.5…16 k，Q=1.1，单段 ±12 dB，相邻串扰 <0.1 dB |
| 压缩 | 三段（200 Hz / 2.5 kHz 分频） | 攻 8 ms / 释 180 ms，3–5:1，阈值 −14…−20 dBFS |
| 限幅 | 2 ms 前视 | 即时下压、8 ms 回弹，天花板 −0.9 dBFS |

7 个预设：原声 / 人声 / 流行 / 摇滚 / 爵士 / 重低音 / 蝰蛇式。开启后推流会先过这条链，
推 WAV 时自动读文件（单声道会复制成两路、采样率不符会重采样到 48 kHz）。
实时开销 0.27 ms / 10 ms 块。

### 双 DAC 模式（`work/eth_audio/rtl/dac_split.v`）

板载 ES8388（G17）与外接 ES9038Q2M（Y11）原来是一条数据线纯扇出，现在按 LRC 门控成两路：

| 模式 | 控制字节 | 板载 | 外接 | 用途 |
| --- | --- | --- | --- | --- |
| M0 同源 | `'m'` | 立体声 | 立体声 | 两个 DAC 音质 A/B |
| M1 左右分离 | `'o'` | 只放左 | 只放右 | 双 DAC 各管一边 |
| M2 外接独占 | `'p'` | 静音 | 立体声 | 配单声道素材做高音质单声道 |

> 界面显示的是"本机下发"，因为 12 字节状态包里没有这个字段；真值看串口状态行的 `dm=`。
> 验证素材：`材料库/04-实测记录/音频样本/2026-11-02_dac_L440_R880.wav`（左 440 / 右 880）。

## 部署注意（2026-10-28 实测，两个都踩过）

### 1. 这个工作区是「低完整性目录」，里面的 exe 起不来

```
icacls "D:/deepseek herness/work/pc_app/dist/ZYNQ-AudioConsole.exe"
  -> Mandatory Label\Low Mandatory Level:(I)(NW)
```

带这个标签的可执行文件被 Windows 拦下，**双击什么都不发生**（连错误框都没有）。
同一份文件 `cp` 到普通目录立刻能跑（md5 一致，已实测）。

**做法**：运行副本放在工作区**之外**：

| 位置 | 用途 |
|---|---|
| `D:/ZYNQ-AudioConsole/ZYNQ-AudioConsole.exe` | 正式副本 |
| `C:/Users/<你>/Desktop/ZYNQ-AudioConsole.exe` | 桌面快捷入口 |

`work\pc_app\dist\` 里那份是构建产物，**不要直接双击**。

### 2. `run_console.cmd` 必须 ASCII + CRLF

`cmd.exe` 用 OEM 代码页读 `.cmd`，UTF-8 中文注释 + 裸 LF 换行会让解析器出问题
（表现为窗口一闪而过、什么都没发生）。已改成纯 ASCII + CRLF。

### 3. Edge 的两个参数要一起用

| 参数 | 为什么 |
|---|---|
| `--disable-gpu` | 不加的话 GPU 进程会崩，窗口起不来 |
| `--no-sandbox` | 受限会话里渲染进程拉不起来 → **整页白屏** |
| `--test-type` | 配 `--no-sandbox` 用，压掉顶部那条"你使用的不是受支持的命令行标记"黄色警告条 |

只加 `--no-sandbox` 会有丑警告条；只去掉它会白屏。三个必须配套。

## 硬件前提：先插网线，再烧写

板子**开机时会自协商 PHY 并配置 MAC**。如果开机那一刻 `link=0`（网线没插），
RX 通道不会正常挂上，之后即使插上网线：**上行（板→PC）正常，下行（PC→板）一个包都收不到**，
表现为「切档/底噪/自检音/推流全都没反应」，而波形却是活的。

判据（板子串口开机横幅）：

```
p4 AN100 bmcr=1100 bmsr=7949 link=0 wait=3000 ms   <- 坏的
p4 AN100 bmcr=1100 bmsr=7949 link=1 ...            <- 正常
```

`bmsr` bit2 = Link Status，bit5 = Auto-Neg Complete，这两位都必须是 1。

**正确顺序**：插网线 → 确认 PC 该网口拿到 `169.254.x.x` → 再烧写/上电。
